# GitHub Pages向けセキュリティ修正（2026-10-15）

## 今回の変更

- Next 16.3.8、React/React DOM/RSC 19.2.8、Vite 8.0.16、plugin-rsc 0.5.36、vinext 1.0.1、Cloudflareプラグイン/関連ツール等へ更新しました。公開後7日間の待機・ビルド許可ルールは維持しています。pnpm 11が実際に読む`pnpm-workspace.yaml`とpackage.jsonの修正版overrideをそろえ、ロックも更新しました。
- 「設定」に「バックアップから復元」「この端末の記録を削除」を追加しました。初回の相棒選択画面と、保存データの読込みに失敗した画面からも復元・削除できます。
- 復元前にアプリ識別子・形式バージョン・25MiB上限・全記録/設定/相棒データ・日付・重複・おほしさまを検証します。対象件数と相棒を表示し、置換への同意後に反映します。ファイルはネット送信しません。現在のデータとの自動マージは行いません。
- 削除には「削除」の入力とチェックによる確認が必要です。保存済み記録・設定・相棒・星に加え、Pagesのdeviceスコープの下書き/タイマーだけを消します。他アプリや別スコープのキー、別ブラウザ、書出し済みJSONは消しません。`localStorage.clear()`は使用しません。
- 復元・削除時には、別タブの古い記録/下書き/タイマーの書込みを変更マーカーで無効化し、画面を開き直します。保存失敗の再試行や下書きflushにもガードを適用しました。マーカーは個人情報を含まない管理用値で、記録削除後も残ります。
- 下書きは最終保存から7日を超えたもの、時刻が不正なものを次の利用時に整理します。Sitesではログイン中のユーザースコープだけを対象にします。**保存済みの毎日の記録は自動削除しません**。
- 保存領域不足や不正JSONでは既存の記録を消さず、失敗を表示します。複数キーの削除はトランザクションではないため、一部削除失敗を成功扱いしません。復元後の下書き整理に失敗した場合は、記録自体は復元済みであることを別途案内します。

## バックアップと後日のドメイン移行

1. 現在のURLの「設定」→「自分の記録を書き出す」でJSONを保存します。体重・メモも含まれるので、共有先とファイルの保管場所に注意してください。
2. 新しい専用ドメインに、今回の復元機能を含むアプリを配置します。配置・DNS設定は今回行っていません。
3. 新しいURLの初回画面、または「設定」→「バックアップから復元」でファイルを選びます。相棒・件数・星を確認し、置換への同意後に復元します。
4. 新しいURLで記録・相棒・衣装・星が正しく表示されることを確認します。それから旧URLの記録を必要に応じて削除してください。最初から旧記録を消さないでください。

今回以降の書出しには`starLedger`を追加し、後から記録欄を空にした日も獲得済みの星IDを保持します。以前の`mochi-days-export` version 1（Sitesの書出しを含む）も読めますが、古い形式に入っていなかった獲得日・項目は復元できません。その場合は現在の記録の獲得分と残りの残高を引き継ぎ、星の総数を維持します。新形式では以後の書出しでも残高とIDを保持します。

ドメインを変えてもブラウザの記録は自動移行されません。また、Safariタブとホーム画面アプリの保存先が別になる場合は、使う側で復元してください。稼働中の旧バージョンのタブはすべて閉じ、新しい版を開いてから復元・削除してください。

## 同じGitHub Pagesドメインでの2アプリ公開について

現在の`mochi-days:v1`と専用の補助キーを維持するので、既存記録を自動で引っ越したり初期化したりしません。「もちと、かいご」側は独自のキーを使い、全オリジンを消す操作を入れないでください。今回その別リポジトリは変更していません。

**キーの分離は混同防止であり、同一オリジンのJavaScript同士のアクセス制御にはなりません。** 同じ`alexahelth.github.io`内では読み取りが可能である点は残ります。完全な分離には、専用ドメインや無料の別ホスト名が必要です。今回の変更はこの問題を解消したとは扱いません。
